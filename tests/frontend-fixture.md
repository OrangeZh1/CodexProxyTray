# 延迟 IPC 验收

在主线程安排的验收阶段启动：

```text
npm run build:ui
node tests/frontend-fixture.mjs
```

只监听 `127.0.0.1:4174`；测试页为 `/`，控制页为 `/__qa`。页面一直标记 **QA 模拟 IPC**，使用实际 `ui/` 源码构建的 `dist/`，不读取或修改真实代理、助手、注册表、GitHub。不会使用真实预览端口 4173。

可用 `QA_DIST` 指向已通过 GitHub CI 构建并下载的 `frontend-dist` 目录，直接检查同一份生产页面，无需在本机重新构建。`QA_PORT` 可选择另一个空闲回环端口。

用量记录、服务商、性能、HTTP 状态和 `get_usage_prices` 返回的模型单价均为合成演示数据。fixture 不读取真实 Codex 会话，也不访问 models.dev；其中价格不能作为真实供应商报价。旧格式示例的性能和状态为未知，已知性能标记为日志估算。当前真实 Codex 用量日志没有 HTTP 状态时仍返回未知，不可用演示的合成 200 / 429 证明原生数据存在这些字段。

合成记录按固定的绝对时间槽生成，同一事件的时间、模型与 token 不因下一次轮询重算而变化；范围只筛选已有事件。只有跨过新事件时间槽才增加记录，避免用整页重新生成的数据误验“新记录”动效。

无需等待时间槽时，可通过控制状态 `qa_usage_extra_records` 注入最多 20 条合成元数据。每条固定 `at` 毫秒时间、模型、输入/缓存输入/输出 tokens，可指定 `provider` 和 `source_kind`；合计校验为输入加输出。只在所选范围内加入，所有摘要、模型、服务商和时段聚合保持一致，性能与 HTTP 状态保持未知。重复读取不会改写注入时间，清除使用 `{"state":{"qa_usage_extra_records":[]}}`。该入口不读取真实日志或私有文件，也不改变真实 Codex 记录。

可选的 `QA_PRICE_CATALOG` 只读取显式指定的、任务目录中的 models.dev 公开价格快照。该 JSON 使用 `source`、原始 `fetched_at`、完整价格映射 `models`、包含缺价字段的模型清单 `catalog`，以及可选的 `demoModels`。不设置此环境变量时，CI 和常规 fixture 继续使用上面的合成单价。

启用公开缓存时，用量仍为演示数据，模型名称可选用快照中的精确 ID，价格清单使用公开缓存；左下角提示和 `GET /__qa/state` 的 `price_catalog` 标明来源、原始时间和未验证原生同步。fixture 不回源、不改写快照，不修改或清除浏览器已有自定义价格。`force:true` 保留原始下载时间，并明确返回只读演示提示，不冒充本轮原生同步成功。

`get_usage_exchange_rate` 始终使用隔离的 **7.25 合成汇率**，即使启用了公开价格快照，也不代表实际 ECB 汇率或原生请求已验证。可用该命令的延迟、失败和取消规则检查币种加载态；`POST /__qa/control` 传 `{"state":{"qa_fx_unavailable":true}}` 可返回未知汇率，恢复为 `false` 或重置 fixture 后重新读取。fixture 不访问汇率服务。

`record_ui_event` 只接受与原生端一致的闭集事件名称，映射为固定中文日志；CLI、应用、价格、更新和流量操作也有对应的模拟记录。日志保留最近 200 条，自动用量读取成功不会逐次写操作日志，所有记录均限本 fixture。

价格快照返回 `auto_sync_enabled`。`set_usage_price_sync({enabled})` 在 fixture 内模拟助手级设置并写固定日志，不修改真实偏好文件、不启动后台联网。`open_usage_prices_dir` 只记录请求，不打开系统目录；`reload_usage_prices` 只返回已有缓存，不联网、不改变下载时间。状态 `qa_prices_bad_cache:true` 可模拟本地缓存损坏：返回错误并保留此前目录、单价和自定义覆盖。

控制页可为具体命令设置延迟和成功、失败、取消结果。“仅下一次”是一次性规则；取消勾选后持续生效。`get_status` 供后台轮询使用，检查断线时可设置持续延迟。页面没有通用手动刷新或重新检测操作，版本检查、用量同步和模型价格同步保留手动入口。

| 场景 | 控制与操作 | 验收点 |
|---|---|---|
| 独立加载 | `get_runtime_connections` 延迟 2500ms，点击实时连接；再检查内存读取 | 只有发起项加载，守护、另一项详情和侧栏不转圈 |
| 守护开关与过渡 | 先不延迟反复暂停/恢复，再给 `set_enabled` 延迟 2500ms；检查失败和取消 | 快速回复不闪现转圈；慢回复仅该按钮加载且保持品牌色；暂停为正方形、不显示计时，恢复展开并从新会话计时；重开提示条平滑收放 |
| 重叠动作 | 分别给 `save_proxy`、`save_system` 延迟 4000ms、2000ms，保存代理并切换另一项偏好 | 各自加载和结束；旧响应不覆盖新状态 |
| 继续编辑 | `save_proxy` 一次延迟 4000ms，提交地址 A，返回前把输入改为 B | B 保留，提示当前输入尚未保存；后续轮询不改回 A |
| 即时偏好 | `save_system` 一次延迟 4000ms，切换登录自启，再切换启动目标 | 仅发起项加载；各项回复不撤销另一项待保存选择，失败项恢复实际值 |
| 失败、取消 | 为具体动作各排一次 `error`、`abort`，使用有效表单值触发 | 仅该动作结束加载；错误可见；其他动作状态不受影响 |
| 断线恢复 | 点击模拟断线，等待轮询；再恢复连接 | 显示持续断线提示；后台轮询恢复后清掉连接错误并启用操作 |
| 迟到的断线失败 | 给 `get_status` 持续延迟 4000ms，等一次轮询开始；模拟断线再恢复，清除规则并等待下一次轮询 | 新响应恢复连接后，旧请求失败不会再次把页面标成断线 |
| 更新 | 延迟 `check_updates` 并点击检查更新，再检查失败分支；也可延迟 `open_release` | 只有对应控件加载，失败不留旧的更新说明；发布按钮仅记录模拟操作，不打开浏览器 |
| 网页详情 | 打开网页连通性详情并查看 fixture 请求历史 | 展示已有探测结果，打开详情不发起 `check_connectivity`；没有手动探测按钮 |
| 流量采集 | 延迟 `enable_traffic` / `disable_traffic`，分别模拟成功、失败、取消 | 只对应统计控件加载，权限分支明确；fixture 不发起真实 UAC 或 ETW |
| 用量范围 | `get_usage` 延迟 2500ms，日期面板先确定近 7 天再确定近 30 天；检查失败、取消；编辑日期、时间和日历后取消或确定 | 草稿及取消不请求；只有范围控件或确定按钮加载；较早范围回复不能覆盖新范围；失败保留上次数据 |
| 用量价格 | `get_usage_prices` 延迟或失败，打开设置，关闭自动同步后立即同步；搜索、保存、取消和移除自定义价格 | 立即同步传 `force:true` 且只有该按钮加载；目录缓存读不冒充手动同步成功；节流、失败、取消可见；自定义覆盖不丢失 |
| 定价对话框 | 用量设置打开“管理模型定价”，再从列表或通用入口编辑；依次关闭编辑和定价 | 目录只有一个所有者；编辑关闭后保留定价并回到原入口，定价关闭后保留设置并回到管理入口；币种、读取间隔和图表仍在设置中 |
| 用量明细与设置 | 切换摘要趋势，展开 token；切记录、服务商、模型；改页数、跳页、列和状态筛选；打开明细和设置 | 默认 20 条，可选 10 / 20 / 50 条；纯界面筛选和价格计算不重读会话；未知性能与状态显示 `—`；图表悬停及键盘有时段详情 |
| 用量读取设置 | 暂停自动读取、调整间隔并恢复，然后离开页面 | 设置变更不额外立即扫描；每页只保留一个间隔任务，离开页面后清除 |
| 主动同步用量 | `get_usage` 延迟后点击用量页同步，再重复点击；后台读取在途时再点同步；同步在途时切换范围 | 只有发起的同步按钮加载；同范围复用在途读取；背景同步不点亮手动按钮；旧范围同步结果不覆盖新范围；失败保留已有结果 |
| 人民币费用 | `get_usage_exchange_rate` 延迟、失败或取消后选择 CNY；检查未知汇率，再恢复 7.25 合成值；读取在途时切回 USD | 只有币种控件加载；未知汇率不猜人民币费用；费用、图表与明细按原始美元换算；模型单价仍为美元；晚到汇率不撤销新选择 |
| 趋势样式 | 在用量设置中选择柱状图和曲线面积图 | 仅保存本机显示偏好，不重新读取用量、价格或汇率；未知时段不跨段连线，时段键盘提示仍可用 |
| 新记录提示 | 同一范围第一页返回“旧记录完全保留＋新增最新记录”；再改单价或币种、切页和筛选 | 只有新增记录淡入和短暂提示，旧行节点保留；首次、切范围和纯显示变化不播放整表动效；5 / 30 秒设置可选，20 秒保留兼容 |
| 托盘首帧与重开 | 客户端模型先延迟首次 `get_status`，再模拟失焦、重获焦点并延迟新读取 | 首次状态返回前不报告 `frontend_ready`；重获焦点保留已有摘要、代理地址和有效操作，不先清空为未知 |
| 工作目录选择 | 客户端模型延迟 `choose_cli_workdir`，分别返回合成目录、`null` 或错误；选择在途时导航，或与输入框自动保存重叠 | 只有浏览按钮在选择阶段加载，随后保存归输入框；取消、错误与过期选择不保存；旧自动保存完成后再保存后选目录，不记录路径 |

每个独立场景前重置 fixture 并刷新测试页。延迟响应在请求进入时捕获状态，方便重现“旧读取比新保存更晚返回”。`abort` 是模拟 IPC 的 `AbortError` 拒绝，用于检验清理逻辑，不表示产品已经提供用户取消按钮。断线可能发生在模拟操作已经应用、但回复尚未返回之后，不能把它当作事务回滚测试。

也可直接使用仅测试用 API，便于主线程通过工具准备场景：

```text
POST /__qa/control
{"rule":{"command":"save_proxy","delayMs":4000,"outcome":"success","once":true}}

POST /__qa/control
{"online":false}

POST /__qa/control
{"online":true,"clearRules":true}

POST /__qa/control
{"reset":true}

GET /__qa/state
```

`/__qa/state` 显示当前模拟状态、规则、最近请求及开始/结束时间，可供人工界面对照。验收完成后，只关闭本 fixture 的进程。未经执行的人工界面场景不能因纯逻辑或 SSR 通过而标记通过。

窗口置顶通过客户端检查中的隔离 `appWindow` 模型覆盖成功、延迟和失败；loopback fixture 不提供真实窗口控制，不会置顶用户的其他窗口。

`choose_cli_workdir` 在 fixture 中仅返回固定合成目录，不打开真实系统对话框、不检查或写入该目录。控制状态 `qa_picker_cancel:true` 可模拟原生对话框取消并返回 `null`；IPC 的 `abort` 拒绝与对话框取消是两个独立场景。普通网页预览中的浏览工作目录按钮保持禁用。
