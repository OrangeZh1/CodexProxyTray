# 延迟 IPC 验收

在主线程安排的验收阶段启动：

```text
npm run build:ui
node tests/frontend-fixture.mjs
```

只监听 `127.0.0.1:4174`；测试页为 `/`，控制页为 `/__qa`。页面一直标记 **QA 模拟 IPC**，使用实际 `ui/` 源码构建的 `dist/`，不读取或修改真实代理、助手、注册表、GitHub。不会使用真实预览端口 4173。

控制页可为具体命令设置延迟和成功、失败、取消结果。“仅下一次”是一次性规则；取消勾选后持续生效。`get_status` 同时供后台轮询和日志刷新使用，加载态验收宜设为持续延迟，避免一次规则被后台轮询先消耗。

| 场景 | 控制与操作 | 验收点 |
|---|---|---|
| 独立加载 | `refresh_status` 持续延迟 2500ms，点击重新检测 | 只检测按钮加载，其他按钮不转圈 |
| 重叠动作 | 分别给 `save_proxy`、`save_system` 延迟 4000ms、2000ms，保存代理并切换另一项偏好 | 各自加载和结束；旧响应不覆盖新状态 |
| 继续编辑 | `save_proxy` 一次延迟 4000ms，提交地址 A，返回前把输入改为 B | B 保留，提示当前输入尚未保存；后续轮询不改回 A |
| 即时偏好 | `save_system` 一次延迟 4000ms，切换登录自启，再切换启动目标 | 仅发起项加载；各项回复不撤销另一项待保存选择，失败项恢复实际值 |
| 失败、取消 | 为具体动作各排一次 `error`、`abort`，使用有效表单值触发 | 仅该动作结束加载；错误可见；其他动作状态不受影响 |
| 断线恢复 | 点击模拟断线，等待轮询；再恢复连接 | 显示断线、可手动重新检测；恢复后清掉连接错误并启用操作 |
| 迟到的断线失败 | 给 `get_status` 持续延迟 4000ms，等一次轮询开始；模拟断线再恢复；清除规则并点击重新检测 | 新响应恢复连接后，旧请求失败不会再次把页面标成断线 |
| 更新 | 延迟 `check_updates` 并点击检查更新，再检查失败分支；也可延迟 `open_release` | 只有对应控件加载，失败不留旧的更新说明；发布按钮仅记录模拟操作，不打开浏览器 |
| 网页探测 | 延迟 `check_connectivity`，同时触发日志刷新 | 只有各自按钮加载；后台探测状态不点亮手动按钮 |
| 流量采集 | 延迟 `enable_traffic` / `disable_traffic`，分别模拟成功、失败、取消 | 只对应统计控件加载，权限分支明确；fixture 不发起真实 UAC 或 ETW |

每个独立场景前重置 fixture 并刷新测试页。延迟响应在请求进入时捕获状态，方便重现“旧读取比新保存更晚返回”。`abort` 是模拟 IPC 的 `AbortError` 拒绝，用于检验清理逻辑，不表示产品已经提供用户取消按钮。断线可能发生在模拟操作已经应用、但回复尚未返回之后，不能把它当作事务回滚测试。

也可直接使用仅测试用 API，便于主线程通过工具准备场景：

```text
POST /__qa/control
{"rule":{"command":"save_proxy","delayMs":4000,"outcome":"success","once":true}}

POST /__qa/control
{"online":false}

POST /__qa/control
{"online":true,"clearRules":true}

POST /__qa/control
{"reset":true}

GET /__qa/state
```

`/__qa/state` 显示当前模拟状态、规则、最近请求及开始/结束时间，可供人工界面对照。验收完成后，只关闭本 fixture 的进程。未经执行的人工界面场景不能因纯逻辑或 SSR 通过而标记通过。
